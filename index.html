The permission model

An identity is qualified by its issuer. The same name at another issuer does not inherit access. An administrator grants explicit actions on regions, tenants and resources; switching login method does not reset a resource budget.

Sensitive operations can require a second, time-limited approval. That approval is bound to the requesting principal and exact operation. Workload failover checks the complete consistency group at both endpoints.

Revocation on the next request

The SAML exercise checks current authorization on each protected request. Removing an operator group changes what an existing session can do. Signed Global Token Revocation requests remove sessions and deny otherwise unexpired OAuth access tokens for the selected issuer and subject.

Group snapshots use a separate debug protocol. The Global Token Revocation profile follows Okta's documented Universal Logout flow; the underlying GTR specification remains an evolving draft.

Know what the laboratory proves

These are executable debug integrations. Local logical regions and ordinary worker processes exercise the real Rust authorization, limiter and failover code. The SAML lab uses local SQLite authorization logs and loopback HTTP.

Production Raft event delivery, production SAML hosting and live Okta interoperability remain separate work. The guides distinguish local IAM fixtures from opt-in real AWS verification, and explain resource teardown explicitly.

Run without cloud resources

Start with the SAML local run or the native Kubernetes exercise. The default local exercises create no AWS resources. Real EKS verification is an explicit, separate option with temporary charges and a cleanup audit.
