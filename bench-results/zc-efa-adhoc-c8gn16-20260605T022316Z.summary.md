# zc-efa-adhoc-c8gn16-20260605T022316Z

Purpose: validate whether AWS EFA/libfabric can move data before wiring it into
the WAL transport abstraction.

Topology:

- Region/AZ: `us-east-2/us-east-2c`
- Instances: two adhoc `c8gn.16xlarge`
- Node0: `i-0d92a2aff91df7210`, private `172.31.44.136`, public `52.14.22.210`
- Node1: `i-0f001e8151ea63422`, private `172.31.47.102`, public `18.219.57.103`
- EFA: one `efa` ENI per node, security group self-ingress all traffic
- Termination: helper issued terminate after logs were captured

Setup:

- Installed AWS EFA installer `1.48.0` with `--skip-kmod --skip-mpi --skip-plugin --no-verify`.
- Post-reboot libfabric: `/opt/amazon/efa/bin/fi_info 2.4.0amzn3.0`.
- Post-reboot EFA domain: `rdmap71s0-rdm`.

Results:

- `fi_info -p efa -t FI_EP_RDM`: succeeded on both nodes.
- `fi_pingpong -p sockets -e rdm 172.31.44.136`: succeeded over private IP,
  `4k`, `1000` iterations, about `107 MB/s`, `38 us/xfer`.
- `fi_pingpong -p efa 172.31.44.136`: timed out before transfer summary.
- `fi_pingpong -p efa -f efa -e rdm`: timed out.
- `FI_EFA_ENABLE_SHM_TRANSFER=0 fi_pingpong -p efa -f efa`: timed out.
- `fi_pingpong -p efa -f efa -e dgram -d efa_0-dgrm`: timed out.

Conclusion:

Provider discovery is not enough. The planner must require a completed
cross-host provider data smoke before a `libfabric_efa` plan is representative.
For now, TCP mux remains the validated WAL transport and libfabric/EFA is a
planned transport lane shape gated behind a successful data smoke.
